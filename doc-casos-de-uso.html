Imagineer — casos de uso e rotas

Mapa completo de como um usuário interage com o sistema hoje — do EPUB importado até a imagem catalogada — e o contrato exato de cada rota da API implementada até a Etapa 6.7 (incluindo o item 3.4e, sugestões persistidas). Gerado a partir de ESPECIFICACAO.md e do código em imagineer/.

27 de setembro de 2026 41 rotas implementadas

Visão geral

O Imagineer ajuda um leitor com afantasia a transformar um livro (EPUB) em imagens de referência: primeiro identifica quem/o quê aparece em cada capítulo, depois monta o texto (prompt) que descreve um retrato solo ou uma cena, e por fim guarda a imagem gerada numa ferramenta externa, formando um catálogo visual do livro.

Cinco entidades sustentam o fluxo: Elemento (quem/o que é — não muda) e EstadoElemento (como está num ponto da história — muda) resolvem a consistência visual; Frame é o recorte que vira prompt, com tipo distinguindo retrato solo (PERSONAGEM) de cena com vários elementos (CENA); Prompt e Imagem fecham o catálogo. Uma sexta peça, PerfilRenderizacao, carrega o estilo visual, independente do livro.

Todo o texto do sistema — nomes de campo, mensagens, rotas — é em português, com exceções pontuais registradas: Frame (nome da entidade) e o nome de uma variável de ambiente.

Fluxo passo a passo

A sequência completa, da Etapa 2 da especificação — cada caso de uso abaixo é um recorte deste fluxo.

  1. Usuário importa o EPUB no app.
  2. App envia o EPUB para o servidor. POST /livros
  3. Servidor estrutura o arquivo em capítulos.
  4. Servidor devolve a estrutura para o app.
  5. Usuário escolhe um capítulo. GET /capitulos/{id}
  6. Servidor chama a IA para sugerir personagens, ambientes, objetos, criaturas e cenas — usando o último estado conhecido de cada elemento já cadastrado. POST /capitulos/{id}/sugestoes
  7. Usuário revisa: confirma, ajusta ou descarta cada sugestão; decide se cada elemento mantém o estado atual ou ganha um novo. POST /livros/{id}/elementos
  8. Servidor usa o histórico (estado dos elementos escolhidos) para montar o prompt de imagem. POST /frames/{id}/prompts
  9. Usuário copia o prompt e gera a imagem numa ferramenta de IA externa, gratuita.
  10. Usuário importa a imagem gerada de volta para o app. POST /prompts/{id}/imagens
  11. Imagem é salva, associada ao frame/elementos de origem, compondo o catálogo.

Casos de uso

UC1 — Importar e organizar um livro

Levar um arquivo EPUB da máquina do usuário até uma biblioteca navegável de capítulos.

Ator
Usuário (único, sistema pessoal)
Pré-condição
Nenhuma
Pós-condição
Livro com capítulos estruturados, pronto para revisão
  1. Usuário seleciona o arquivo .epub. POST /livros
  2. Servidor extrai metadados (título, autor, idioma) e divide o texto em capítulos pelo spine/TOC do EPUB; descarta sumário, navegação e páginas sem texto útil; sugere capítulos não-narrativos como ignorado.
  3. Resposta traz o livro criado e, se algum outro livro já importado tiver o mesmo identificador do EPUB, avisa sem bloquear (livros_semelhantes).
  4. Usuário revê a biblioteca. GET /livros
  5. Usuário abre o livro para ver a estrutura de capítulos. GET /livros/{id}
  6. Usuário corrige metadados errados (comum: EPUBs convertidos trazem metadado de outro livro) ou desfaz uma sugestão de "ignorado". PATCH /livros/{id} PATCH /capitulos/{id}
  7. Usuário abre um capítulo específico para ler o texto completo. GET /capitulos/{id}
A importação nunca descarta conteúdo por conta própria — só sugere. É o mesmo princípio usado depois para elementos e estados: a IA/o parser sugerem, o usuário confirma.

UC2 — Descobrir e confirmar elementos de um capítulo

Transformar o texto de um capítulo em personagens/ambientes/objetos/criaturas cadastrados, com o estado (aparência) de cada um naquele ponto da história.

Ator
Usuário, com apoio da IA
Pré-condição
Livro importado; modelo_extracao e chave de API configurados
Pós-condição
Elementos cadastrados, cada um com um Estado válido até este capítulo
  1. Usuário pede sugestões do capítulo. POST /capitulos/{id}/sugestoes
  2. Servidor lê o estado vigente de cada elemento já cadastrado até este capítulo, manda isso + o texto do capítulo para a IA, e recebe de volta elementos sugeridos (tipo, nome, descrição de identidade, se deve manter o estado atual) e cenas sugeridas (candidatas a virar Frame quando confirmadas, com participantes).
  3. Cada sugestão de elemento já vem casada com um elemento existente por nome (ignorando caixa/acento), quando aplicável — elemento_id preenchido significa "já cadastrado".
  4. Para um elemento novo, o usuário cadastra, opcionalmente já com o estado deste capítulo. POST /livros/{id}/elementos
  5. Para um elemento já existente com aparência nova, o usuário registra outro estado. POST /elementos/{id}/estados
  6. Se a IA sugeriu o mesmo personagem em capítulos diferentes sem casar pelo nome ("Sextus Hospius" num, "Hospius" noutro), o usuário busca todas as menções e confirma as duas juntas, como o mesmo Elemento, com um Estado por capítulo. GET /livros/{id}/sugestoes-elemento?nome=... POST /livros/{id}/elementos
  7. Usuário revisa a lista de elementos do livro, filtrando por tipo se quiser. GET /livros/{id}/elementos
  8. Usuário confere como cada elemento estava até um ponto específico da narrativa (útil para conferir consistência). GET /capitulos/{id}/estados-vigentes
Cadastrar o mesmo elemento (mesmo tipo + nome, no mesmo livro) duas vezes responde 409 — a extração automática reencontra personagens em capítulos diferentes, então essa restrição evita duplicata.
Cada elemento/cena sugerido tem id próprio, salvo no banco (item 3.4e) — sugestoes_elemento_ids em POST /livros/{id}/elementos (ou, para um elemento já existente, POST /elementos/{id}/estados-de-sugestoes) confirma várias sugestões escolhidas de uma vez, criando um Estado por capítulo, sem copiar a descrição à mão em cada uma.

UC3 — Gerar o retrato de um personagem

Produzir o texto de prompt para uma imagem de UM elemento sozinho, sem citar mais ninguém.

Ator
Usuário, com apoio da IA
Pré-condição
Elemento com ao menos um Estado; modelo_prompt configurado; perfil de renderização definido (no pedido ou como padrão do livro)
Pós-condição
Um Prompt salvo, pronto para colar numa ferramenta de imagem externa
  1. Usuário cria um frame do tipo PERSONAGEM, ligado a exatamente um Estado. POST /capitulos/{id}/frames
  2. titulo é opcional aqui — sem ele, o servidor gera "Retrato de <nome>" sozinho.
  3. Usuário pede o prompt. POST /frames/{id}/prompts
  4. Servidor faz a leitura profunda do estado (relê o capítulo de origem e reescreve EstadoElemento.descricao — o livro é a fonte de verdade, mesmo sobrescrevendo o que foi digitado à mão) e monta o prompt usando só essa descrição, o perfil de renderização e, se houver, o comentário do usuário. Nenhum outro elemento é citado.
  5. Usuário copia texto da resposta e gera a imagem fora do sistema.
Por padrão (prioridade_ia: ECONOMIA) a leitura profunda de um estado só acontece uma vez; pedir o prompt de novo é rápido porque reaproveita. Com QUALIDADE, relê toda vez.

UC4 — Montar e gerar uma cena com vários elementos

Produzir o prompt de um momento da narrativa com vários elementos interagindo — quem, onde, o quê, sem ambiguidade.

Ator
Usuário, com apoio da IA
Pré-condição
Um ou mais elementos com Estado; modelo_extracao e modelo_prompt configurados
Pós-condição
Um Prompt salvo, fiel ao que o usuário escreveu sobre a cena
  1. Usuário cria um frame do tipo CENA (padrão), com título, descrição e atributos situacionais escritos à mão, ligado aos estados dos elementos que participam — ou direto de uma cena sugerida (item 3.4e): com sugestao_cena_id, título/descrição/atributos vêm da sugestão e os estados são resolvidos sozinhos a partir dos participantes já confirmados. POST /capitulos/{id}/frames
  2. titulo é obrigatório aqui (a não ser que venha de sugestao_cena_id) — é a conta do próprio usuário sobre a cena, e o sistema não tem como inventar isso.
  3. Se precisar ajustar quem participa depois de criado. PUT /frames/{id}/estados
  4. Usuário pede o prompt. POST /frames/{id}/prompts
  5. Servidor faz a leitura profunda de cada estado envolvido, depois fundamenta o frame — relê o capítulo para confirmar quem/onde/o quê contra o que foi escrito, guardando o resultado em contexto_do_livro. Isso não sobrescreve título/descrição: é apoio, com prioridade menor que a escrita do usuário.
  6. Servidor monta o prompt na ordem: comentário do usuário (se houver) > descrição do frame > contexto do livro.
Testado com IA real: quando a fundamentação leu o trecho errado do capítulo (cena longa, vários momentos), o prompt final saiu correto mesmo assim — a prioridade protegeu a descrição do usuário de uma alucinação da releitura automática.
Criar o frame a partir de sugestao_cena_id exige que cada participante já tenha elemento_id confirmado (422, listando quem falta, senão) — confirmar elemento sempre vem antes de confirmar frame.

UC5 — Refinar o prompt, importar a imagem e avaliar

Fechar o ciclo: corrigir o prompt com um detalhe que a IA não captou, trazer a imagem gerada de volta, e registrar o que achou do resultado.

Ator
Usuário
Pré-condição
Um Prompt já existe para o frame
Pós-condição
Imagem catalogada, ligada ao prompt e, por ele, ao frame de origem
  1. Usuário nota algo que faltou (ex.: uma cicatriz mencionada num capítulo seguinte) e pede o prompt de novo, com um comentário. POST /frames/{id}/prompts
  2. Não existe rota separada de "refinar" — é a mesma chamada de sempre, com comentario preenchido, que tem prioridade máxima sobre a leitura automática.
  3. Usuário consulta o histórico de tentativas do frame. GET /frames/{id}/prompts
  4. Usuário copia o texto escolhido, gera a imagem numa ferramenta externa, e importa o arquivo de volta. POST /prompts/{id}/imagens
  5. Usuário anota como a imagem ficou, para comparar modelos depois. PATCH /prompts/{id}
  6. Usuário baixa/exibe o arquivo quando precisar. GET /imagens/{id}/arquivo
Ao abrir um prompt de cena, a resposta também traz referencias_visuais — as imagens-âncora já aprovadas dos elementos envolvidos, para o usuário anexar junto e manter a aparência consistente entre capítulos distantes (o fluxo de geração é manual, fora do sistema).

UC6 — Configurar a integração com IA

Escolher os modelos de IA e o equilíbrio custo/qualidade antes de usar qualquer rota que dependa de IA.

Ator
Usuário
Pré-condição
Nenhuma (a chave pode já vir de variável de ambiente)
Pós-condição
Modelos escolhidos, prontos para as rotas de sugestão e prompt
  1. Usuário vê a lista de modelos disponíveis no OpenRouter — funciona sem chave cadastrada, o endpoint de modelos é público. GET /configuracao/modelos
  2. Usuário escolhe modelo_extracao (sugestões) e modelo_prompt (montagem), e, se preferir não usar variável de ambiente, cadastra a chave pelo app. PUT /configuracao
  3. Usuário decide entre ECONOMIA (padrão — reaproveita leituras já feitas) e QUALIDADE (relê sempre) para a leitura profunda e a fundamentação de frame.
  4. Usuário confere a configuração atual — a chave em si nunca é devolvida, só se existe e de onde veio. GET /configuracao
A chave não é mais cadastrada pelo app: mandar chave_api_openrouter devolve 422. Vale o header X-Chave-API-OpenRouter (por chamada) ou a variável de ambiente do servidor.

UC7 — Gerenciar perfis de renderização

Definir e reaproveitar um estilo visual (aquarela, iluminação, paleta) entre livros diferentes.

Ator
Usuário
Pré-condição
Nenhuma
Pós-condição
Um perfil disponível para usar como padrão de um livro, ou pontualmente num prompt
  1. Usuário cria um perfil com o estilo desejado. POST /perfis-renderizacao
  2. Usuário define esse perfil como padrão de um livro. PATCH /livros/{id}
  3. Ao montar um prompt, o usuário pode usar o padrão do livro ou informar outro perfil pontualmente, no próprio pedido de prompt.
  4. Usuário ajusta o perfil (ex.: mais contraste na iluminação) — vale para os próximos prompts, não reescreve os já gerados. PATCH /perfis-renderizacao/{id}
Apagar um perfil não apaga livros nem o histórico de prompts — a referência vira nula (ON DELETE SET NULL); o texto do prompt já gerado continua fiel ao que foi usado na hora.

POST/elementos/{elemento_id}/mesclarJunta um elemento duplicado a outro

Corpo: {"destino_id": N}. Devolve a ficha do destino. 404 se um dos dois não existe; 422 se forem o mesmo elemento ou de livros diferentes.

Sugestões (IA) implementado

Fase 1 do item 4.4 — identificação de elementos e cenas candidatas, a partir do texto de um capítulo.

GET/capitulos/{capitulo_id}/sugestoesLê as sugestões salvas, sem chamar a IA

Só leitura: nunca chama a IA e não precisa de chave nem de modelo configurados. Devolve a mesma resposta do POST abaixo. Capítulo nunca analisado: gerado_em nulo e listas vazias. Existe porque o POST gera (e cobra) quando o capítulo nunca foi analisado — um leitor não pode usá-lo só para ler.

POST/capitulos/{capitulo_id}/sugestoesOs elementos e cenas sugeridos do capítulo

Não grava Elemento nem Frame — quem confirma é o usuário, pelas rotas de Elementos e Frames. A sugestão em si é persistida, em linhas próprias com id estável (item 3.4e): sem forcar=true, o que já está salvo é devolvido sem chamar a IA de novo (a IA não é determinística — evita respostas divergentes a cada leitura). O casamento com elemento_id é sempre recalculado, mesmo servindo do que já está salvo. A IA sugere uma cena, nunca um Frame — o Frame só passa a existir quando o usuário confirma (item 3.4e, divergência registrada).

Query

CampoTipoObservação
forcarbooleanoopcionalPadrão falso. Só substitui sugestões ainda não confirmadas — as já viradas Elemento/Frame sobrevivem

Resposta — 200

  • gerado_em: quando a última rodada de sugestão deste capítulo chamou a IA
  • elementos[]: id, tipo, nome, descrição de identidade, manter_estado_atual, modelo, elemento_id (nulo = ainda não confirmado)
  • cenas[]: id, cenas candidatas — título, descrição, horário/clima/humor, modelo, participantes[] (cada um com sugestao_elemento_id e elemento_id quando casado)

Erros

  • 404 Capítulo inexistente
  • 422 Sem modelo de extração escolhido · sem chave · texto maior que a janela do modelo
  • 502 Erro do provedor de IA
